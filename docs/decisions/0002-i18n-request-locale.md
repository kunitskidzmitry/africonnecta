# ADR-0002. Локализация на `requestLocale`, а не на `next/root-params`

- **Статус:** принято, подлежит пересмотру
- **Дата:** 2026-09-06
- **Контекст:** WP1 вехи M0, решение Q6 (`i18n` закладывается сразу, запуск на английском)

## Контекст

`next-intl` 4.14 помечает параметр `requestLocale` в `getRequestConfig` как deprecated и
рекомендует переход на `next/root-params` из Next 16.

## Решение

На M0 остаёмся на `requestLocale`.

## Обоснование

Типы `next/root-params` генерируются в `.next/types/root-params.d.ts` во время сборки; до первой
сборки модуль объявлен как `declare module 'next/root-params'`, то есть фактически `any`.
Строить фундамент проекта на API, которое не типизировано до сборки, противоречит правилу
«типы от БД до UI» из §2.2.1 — как раз того предохранителя, который компенсирует отсутствие
второго разработчика.

`requestLocale` работает, типизирован и покрыт тестами каталогов сообщений.

## Последствия

- Технический долг зафиксирован явно, а не забыт.
- Пересмотреть, когда `next/root-params` получит статические типы без предварительной сборки.
- Точка изменения ровно одна: `src/i18n/request.ts`.
