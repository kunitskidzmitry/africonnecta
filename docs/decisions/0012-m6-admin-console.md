# ADR-0012. M6: минимальная Admin Console

- **Статус:** принято
- **Дата:** 2026-09-13
- **Контекст:** §2.5, §10, §13, §11 M6 `docs/implementation-prompt.md`

## Контекст

M6 требует «минимальную Admin Console §13 + метрику пустых выдач». В §2.5 Фазы 1 для
admin явно: очередь верификации + разблокировка; «всё прочее — прямо в БД». Очередь
верификации уже есть с M5.

## Решения

**1. Объём Фазы 1: хаб + пользователи (suspend/unsuspend) + жалобы + метрика поиска.**

Таксономия CRUD, полный браузер `audit_log`, тарифы и ручной ACS с причиной через UI —
не в M6. Админ при необходимости правит их SQL-ом (как §2.5). Очередь верификации
остаётся на `/admin/verification`.

**2. Блокировка = `users.status` (`active` ↔ `suspended`), только RPC.**

Клиент по-прежнему не может писать `status` (grant только `locale`).
`admin_set_user_status` — security definer, reason → `audit_log`, нельзя менять себя и
других админов.

**3. `search_events` — append-only журнал первых страниц поиска.**

Пишется из `runSearch` (без курсора), чтобы пагинация не размывала метрику. Админ видит
долю `exact_count = 0` и `final_count = 0` за окно дней — индикатор холодного старта §10.

**4. Жалобы — список `conversations` с `reported_at`.**

Чтение уже открыто админу по RLS M4; UI только показывает очередь и reason.

**5. Доступ — RLS + server actions, без `/api/v1`.**

Как M3–M5. REST из §7 не вводится в этой поставке.
