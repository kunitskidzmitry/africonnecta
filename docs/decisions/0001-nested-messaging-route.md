# ADR-0001. Вложенный маршрут для отправки сообщений

- **Статус:** принято
- **Дата:** 2026-09-06
- **Контекст:** §7 `docs/implementation-prompt.md`, отступление от `[SRC]`

## Контекст

Исходная спецификация (`docs/transcription.md`, Full SRS §6) задаёт плоский эндпоинт
`POST /messages`.

## Решение

Используем `POST /conversations/{id}/messages` вместо `POST /messages`.

## Обоснование

Плоский эндпоинт вынуждает передавать получателя в теле запроса. Это значит, что право на
переписку приходится проверять по данным, которые полностью контролирует клиент, и проверка
неизбежно оказывается после разбора тела.

Вложенный маршрут делает разговор объектом авторизации: членство в разговоре проверяется по
идентификатору из пути, до чтения тела. Это соответствует правилу deny-by-default из §8 и
убирает целый класс ошибок, при которых отправитель подменяет получателя.

## Последствия

- Создание разговора становится отдельной операцией (`POST /conversations`).
- Клиент обязан знать идентификатор разговора до отправки сообщения.
- Расхождение с исходной спецификацией зафиксировано и должно быть отражено при её обновлении.
