# AfriConnecta

Платформа поиска африканских академических экспертов. Связывает университеты, исследовательские
институты, правительства и НКО с экспертами из Африки и диаспоры.

> **Статус:** веха M0 (фундамент). Продуктовых функций пока нет.

## Документация

| Файл                                                             | Что внутри                                                                                  |
| ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| [`docs/implementation-prompt.md`](docs/implementation-prompt.md) | **Основной документ.** Архитектура, схема БД, API, авторизация, безопасность, план поставки |
| [`docs/transcription.md`](docs/transcription.md)                 | Расшифровка исходных PDF. Источник истины по требованиям, **не редактировать**              |

> ⚠️ **Исходные PDF не хранятся в git.** Оригинал весит 63 МБ и навсегда осел бы в истории,
> замедляя каждое клонирование. Файлы лежат локально в `docs/source/` и внесены в `.gitignore`.
>
> **Следствие: резервной копии у них нет.** Полное содержание перенесено в
> [`docs/transcription.md`](docs/transcription.md), но сами фотографии существуют в
> единственном экземпляре. Храните их отдельно — в облаке или во внешнем хранилище.

## База данных

Локальная разработка идёт на Supabase в Docker. Docker Desktop должен быть запущен.

| Команда            | Действие                                                        |
| ------------------ | --------------------------------------------------------------- |
| `npm run db:start` | Поднять локальный стек (первый запуск качает образы, это долго) |
| `npm run db:stop`  | Остановить                                                      |
| `npm run db:reset` | Пересоздать базу и накатить все миграции с нуля                 |
| `npm run db:types` | Перегенерировать `src/lib/database.types.ts` из схемы           |

Источник истины о схеме — SQL-миграции в `supabase/migrations/` (см. ADR-0003).

> **Изменил миграцию — запусти `npm run db:types`.** CI пока не ловит расхождение
> закоммиченных типов со схемой, это известный пробел из ADR-0003.

После `db:start` доступны Studio на `http://127.0.0.1:54323` и перехватчик почты
на `http://127.0.0.1:54324`.

### Тестовые учётные записи

`npm run db:reset` применяет `supabase/seed.sql` — тестовые данные **только для локальной
разработки**. Справочники в сид не входят: они нужны и в проде, поэтому лежат в миграции.

| Почта                      | Роль               | Пароль        |
| -------------------------- | ------------------ | ------------- |
| `expert@example.test`      | expert             | `password123` |
| `institution@example.test` | institution_member | `password123` |
| `admin@example.test`       | admin              | `password123` |

Идентификаторы в сиде фиксированные — на них будут ссылаться тесты матрицы авторизации.
Домен `.test` зарезервирован стандартом, письма наружу не уйдут.

В начале сида стоит предохранитель: если в базе найдётся учётная запись вне домена
`example.test`, выполнение прервётся с ошибкой. Это защита от `supabase db reset --linked`,
который применил бы сид к подключённому проекту, а не к локальной базе.

## Структура

```
src/
  app/[locale]/     — маршруты, локализованные по языку
  i18n/             — конфигурация локализации и навигационные обёртки
  proxy.ts          — обработчик запросов (в Next 16 заменил middleware.ts)
messages/           — каталоги переводов
tests/              — тесты, не привязанные к модулю
docs/               — см. таблицу выше
```

## Правила, которые не обсуждаются

Полностью — в §0 и §13 `docs/implementation-prompt.md`. Коротко:

1. **Deny by default.** Эндпоинт без явной политики доступа не мержится.
2. **Тесты авторизации пишутся до фичи**, а не после.
3. **Никаких секретов в клиентском коде.** `service_role`-ключ — только на сервере, CI проверяет
   это механически.
4. **`docs/transcription.md` не редактируется** — это расшифровка источника, а не проектное решение.
5. Отступление от `docs/implementation-prompt.md` оформляется как ADR в `docs/decisions/`.

## Локализация

Инфраструктура заложена, запуск — только на английском (решение Q6). Добавление языка:

1. Дописать код локали в `src/i18n/routing.ts`.
2. Создать `messages/<locale>.json`.

Тест `tests/messages.test.ts` уронит сборку, если в новом каталоге не хватает ключей — забытый
перевод не превратится в пустую строку на проде.
